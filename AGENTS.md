## О проекте

`auth-practice` — учебный monorepo-проект для практики авторизации на разных технологиях.

Главная цель проекта: разобраться, как работает авторизация через JWT в HttpOnly cookie, refresh token, CORS, PostgreSQL и разные backend/frontend-фреймворки.

Проект не является production-приложением, но решения по безопасности и архитектуре важно делать близкими к хорошей практике.

## Правила работы

- Для каждой технологии или фреймворка пользователь будет открывать отдельную сессию.
- Первое сообщение в новой сессии может состоять только из названия технологии или фреймворка, например `ExpressJS`. Это сообщение служит для понятного нейминга сессии в списке «Задачи» Codex. Отвечать на такое сообщение не нужно.
- Если первое сообщение кроме названия содержит вопрос или задачу, нужно ответить и выполнить запрос как обычно.
- Не нужно реализовывать всё сразу или вносить изменения в код без явной команды пользователя.
- Если пользователь просит объяснение, консультацию или ревью, нужно только проанализировать код и дать ответ, не изменяя файлы.
- Изменять или создавать файлы можно только по прямой команде пользователя на реализацию.
- Пользователь старается выполнять задачи самостоятельно. Ревью нужно проводить по его запросу.
- Проект учебный, поэтому после внесения изменений нужно кратко объяснить, что изменено, зачем это нужно и какие существенные решения были приняты.
- Не создавать коммиты и не отправлять изменения в удалённый репозиторий. Пользователь делает это самостоятельно.

## Правила ревью

- При ревью явно разделять замечания на:
  - обязательные — ошибки, проблемы безопасности и некорректное поведение;
  - рекомендуемые — общепринятые соглашения и хорошие практики;
  - необязательные — вопросы стиля и удобства.
- Указывать на технически слабые решения прямо и объяснять причины.
- Рекомендовать общепринятые стандарты, соглашения и корректный синтаксис, даже если текущее решение формально работает.

## Общие принципы для всех фреймворков

Для каждого backend желательно реализовать одинаковый API. Точный API-контракт — пути, форматы запросов, ответов и ошибок — будет зафиксирован отдельно до реализации backend.

### Основной flow

- регистрация пользователя;
- логин;
- хеширование пароля;
- выдача `access_token` в HttpOnly cookie;
- выдача `refresh_token` в HttpOnly cookie;
- обновление access token через refresh token;
- logout с очисткой cookie;
- защищённый endpoint `/profile`.

### Важные принципы

- Не хранить JWT в `localStorage`.
- `access_token` хранить в HttpOnly cookie и делать короткоживущим.
- `refresh_token` хранить в HttpOnly cookie и делать долгоживущим.
- Refresh token желательно хранить в базе данных в виде хеша и отзывать при logout.
- На frontend отправлять запросы с `credentials: "include"`.
- На backend настраивать CORS с `credentials: true`.
- Не использовать `origin: "*"` вместе с cookie.
